XMRAnd setup

Use your own wallet and pool. New installs have no wallet, no pool and no automatic mining. Android supports a foreground service. iOS requires personal development signing, a working JIT helper, and keeping XMRAnd open.

1. Enter your mining details

  1. Create your own Monero wallet using a trusted provider. Copy its public receiving address. Never enter a seed phrase or private spend key.
  2. Choose a RandomX/Monero pool. Get its host, port, TLS requirement, account format and password. Some pools want an address; others want wallet.worker or an account.
  3. Enter host:port, wallet/account, password (often x) and optional worker name. Match TLS to the pool's port.
  4. Use algorithm rx/0 for Monero, 1–2 threads initially and memory mode auto. Save then Start. Wait for dataset initialization, pool jobs and accepted shares. Hashrate alone does not prove successful mining.

Pool payout minimums and profitability vary. Watch heat and power use; stop if the device becomes uncomfortable to touch. Mine only on devices whose owner permits it.

2A. Android

  1. Download the signed XMRAnd-Android-arm64.apk from the project releases and install the ARM64 APK on Android 8 or later. The public APK uses a dedicated Android project key. Unsigned source-build output needs your own signing key.
  2. Enter your settings. Allow notifications so you can see mining status.
  3. Tap Start / apply and restart. Check the foreground notification. If Android suspends mining, use Battery optimization settings to allow unrestricted use.
  4. Choose charging-only if desired. Wait for idle additionally waits for screen-off or external power. Stop cancels pending mining.

Automatic start means opening XMRAnd, not boot-time mining.

2B. iPhone / iPad personal signing

Use your own Mac and Apple account. This is a development/sideload workflow, not an App Store/TestFlight JIT release. No publisher account, shared certificate, device registration or signing service is supplied. Free accounts may not support VPN capabilities. Do not assume a free signer or generic IPA re-signer preserves required entitlements.

Requirements
  • iOS/iPadOS 17.4+ for the bundled helper workflow (the miner itself targets 16+), an unlocked device, USB cable, Mac and Xcode.
  • Your own development signing setup supporting the helper VPN entitlements. Check current Apple/upstream requirements before paying for anything.
  • XMRAnd and the matching patched StikDebug and LocalDevVPN. On iOS 26 ordinary debugger attachment alone is insufficient for this app's JIT path.
Build unsigned apps on your Mac

Install CMake and Xcode command-line tools. From a clean source checkout:

export XMRAND_DEPS_DIR="$HOME/xmrand-deps/iphoneos"
export XMRAND_DEPS_SOURCE_DIR="$HOME/xmrand-dependency-sources"
bash scripts/ios/build-libuv-arm64.sh
bash scripts/ios/build-openssl-arm64.sh

# Replace org.example.personal with a prefix you control.
bash scripts/ios/build-public-ios.sh \
  "$HOME/xmrand-deps/iphoneos" "$HOME/xmrand-build" \
  "$HOME/xmrand-output" org.example.personal.xmrand
python3 scripts/ios/prepare-public-helpers.py \
  --app-id org.example.personal.xmrand \
  --prefix org.example.personal \
  --output "$HOME/xmrand-helpers"

Use new build/helper directories. These public tools never log into Apple, access signing keychains or embed profiles. The unsigned IPA cannot be installed until you development-sign it.

Sign with your own account

You can use the unsigned release download without recompiling. Unzip it, then set its Info.plist CFBundleIdentifier to your own ID using PlistBuddy before signing. The project's iOS guide gives the exact commands. Prepare the helpers using that same ID.

  1. On your own Mac open Xcode → Settings → Accounts and add your own account. Enable Developer Mode under device Settings → Privacy & Security, restart and confirm when requested.
  2. Use your own unique IDs: YOUR_PREFIX.xmrand, YOUR_PREFIX.stikdebug, YOUR_PREFIX.localdevvpn and YOUR_PREFIX.localdevvpn.TunnelProv. The miner ID passed to the helper preparer must match exactly.
  3. Open the prepared StikDebug and LocalDevVPN Xcode projects. Choose your own team for each target in Signing & Capabilities. Keep existing capabilities and register the generated personal StikDebug App Group with your own team. LocalDevVPN app and extension need packet-tunnel-provider; the app also needs allow-vpn. If your account cannot provision these, consult official upstream support.
  4. Build and install both helpers using your own development signing. They use xmrand-stikdebug and xmrand-localdevvpn URL schemes. Keep only one matching copy of each installed.
  5. Create an explicit XMRAnd App ID and iOS App Development profile for your own device and Apple Development certificate. It must match the miner ID and have get-task-allow=true. Distribution profiles normally remove debugger access.

Experienced users can sign the unsigned miner using a matching identity already in their own keychain:

APP="$HOME/xmrand-build/xmrig.app"
PROFILE="/private/path/YOUR_DEVELOPMENT_PROFILE.mobileprovision"
security cms -D -i "$PROFILE" -o /private/tmp/xmrand-own-profile.plist
/usr/libexec/PlistBuddy -x -c 'Print :Entitlements' \
  /private/tmp/xmrand-own-profile.plist > /private/tmp/xmrand-own-entitlements.plist
# Inspect application-identifier, team, devices and get-task-allow first.
cp "$PROFILE" "$APP/embedded.mobileprovision"
codesign --force --sign 'Apple Development: YOUR NAME (YOUR ID)' \
  --entitlements /private/tmp/xmrand-own-entitlements.plist \
  --timestamp=none "$APP"
codesign --verify --strict --deep "$APP"

Install your signed app from Xcode → Window → Devices and Simulators. Trust your own developer profile in Settings → General → VPN & Device Management if prompted. Renew before the profile expires using your own account. Keep signing keys/profiles private; remove temporary decoded profile copies after use. Never borrow a publisher's certificate or profile.

3. Pair your own device and enable JIT

  1. Connect by USB to your own Mac, unlock and accept Trust This Computer. Install compatible upstream idevice tools. Find the UDID in Xcode's Devices window.
  2. Create a private pairing file locally:
    umask 077
idevice-tools --udid YOUR_DEVICE_UDID rppairing pair \
  YOUR_COMPUTER_NAME /private/path/pairing.plist
    Keep the device unlocked; approve new Trust prompts. Consult idevice-tools --help if syntax differs in your version.
  3. Transfer privately to that device and import in matching StikDebug. Pairing files are credentials. Never post them to Discord, commit them, upload to pairing websites or use another person's record.
  4. Open matching LocalDevVPN once and approve its local VPN configuration. Complete StikDebug first-run setup. Disable conflicting VPNs if the local tunnel fails.
  5. Return to XMRAnd, Save and Start. The handoff opens the matching helpers and returns. Verify Mining with JIT and accepted shares.

Failed JIT does not silently mine slowly. “Allow slow interpreter” is off by default. Reboots, expired signatures, trust resets or OS updates may require setup again.

4. iOS foreground operation

  1. Keep XMRAnd visible and unlocked with ventilation. It keeps the display awake while actively mining.
  2. Switching apps, system overlays or locking pauses mining; iOS may suspend the process. Return to resume; tap Start if the OS terminated it.
  3. Set charging-only and battery thresholds as desired. Serious iOS thermal state pauses mining until the device cools.

Continuous background/locked-screen iOS mining is not supported. Do not disable device security or bypass background restrictions.

Settings and configuration

  • Pools: Backups are tried in order on failure. New backups inherit primary credentials; advanced JSON supports independent credentials/TLS and enable flags.
  • Threads: 0 uses engine automatic configuration; a number sets the chosen algorithm's profile. “custom” preserves advanced profiles. Lower counts reduce heat.
  • Priority: 0–5, or auto for engine default. OS scheduling can limit its effect.
  • Memory: fast needs roughly 2 GB plus overhead; light uses less RAM but is much slower; auto lets the engine choose. iOS can terminate apps under memory pressure.
  • Battery: Pause at/below threshold and resume at/above the higher threshold. Android temperature resumes 3°C below the limit; iOS uses system thermal state.
  • Advanced JSON: Supported engine options are preserved. Wrapper preferences are under xmrand. JSON cannot enable features omitted from the binary. Public iOS omits HTTP control, GPU mining, MSR and huge pages. Desktop-only options may not work.
  • Apply: Save persists. Android Start/apply restarts; iOS Stop then Start applies settings.
  • Import/export: One JSON object, maximum 256 KB. Import disables autostart. Review the wallet before Start. Exports contain pool passwords and any advanced API tokens; keep them private.

Fresh installs never copy a publisher wallet. Existing app-private user configuration is preserved. Use a distinct worker name on each device.

Troubleshooting

JIT unavailable / helper stuck

Check matching miner ID, Developer Mode, profile expiry, get-task-allow, helper first-run approval, VPN and current pairing. Refresh pairing from your own Mac. Return, Stop then Start. Enable slow interpreter only if you deliberately want it.

No accepted shares

Check account format, algorithm, port/TLS and jobs/errors. Shares depend on difficulty and hashrate; choose a suitable pool and inspect your own pool dashboard.

Closes or overheats

Reduce threads, try light mode, pause and let the device cool. OS memory and thermal limits still apply.

Sharing a release

Share only reviewed source and clean release artifacts. Exclude old lab builds, configs, pairing files, signing keys, profiles and credentials. Unsigned build tests do not prove another person's signing/JIT setup works.

XMRAnd uses XMRig. Preserve upstream licenses and provide required corresponding source when distributing binaries. Helpers retain their own licenses. This guide requires no publisher Apple account.
